## Boundaries and next decisions

1. **Inventory gate passed:** the six work types, three kinds, authoring/data/plan/run/defect surfaces, all ten report destinations, admin/import/CI/AI areas and their evidence strength are mapped to a VAtlassian decision and acceptance check. This is enough to start plan Task 2 without assuming hidden AssureX behavior.
2. **Unresolved vendor details remain explicit:** Sync Now mutation, live defect creation/linking, populated requirement/defect trace exports, exact automation upload contract and import/migration fidelity. No implementation depends on matching these unknown internals; VAtlassian behavior is defined above and can be revised if later authorized observation proves material.
3. **Auditor difference is deliberate:** AssureX menus and reported results are feature evidence, not proof of an immutable, complete audit record. VAtlassian must prove exact approved content, dataset/build/environment, actor, failed attempt, retest, source/link snapshot and evidence hash before a compliant release claim.
4. **No-egress difference is deliberate:** the vendor describes a Forge UI with a [remote backend](https://gudakesa.com/assurex/). VAtlassian's [test-management design](../superpowers/specs/2026-10-20-test-management-first-design.md) uses Atlassian-hosted compute/storage and checks deployed-app eligibility. The separate authentication solution remains outside this inventory.
